# ระบบห้องพยาบาลออนไลน์
วิทยาลัยเทคโนโลยีอุดมศึกษาพณิชยการ

ระบบเก็บประวัติสุขภาพนักเรียน/นักศึกษา บันทึกการเข้ารับบริการห้องพยาบาล นัดหมายติดตามอาการ และแจ้งเตือนผ่านอีเมล ใช้ได้ทั้งบนคอมพิวเตอร์และมือถือ

## เข้าใช้งานที่นี่

### https://hospital-frontend-gray-one.vercel.app

ไม่ต้องติดตั้งโปรแกรมอะไรทั้งสิ้น เปิดเบราว์เซอร์แล้วเข้าที่อยู่ข้างบนได้เลย

# คู่มือสำหรับพยาบาล

--------------------------------------------------
## เข้าสู่ระบบ

1. เปิดเว็บตามที่อยู่ข้างบน
2. กรอกชื่อผู้ใช้และรหัสผ่านที่ได้รับ
3. กดปุ่ม "เข้าสู่ระบบ"

ถ้าอยากดูว่าพิมพ์รหัสผ่านถูกไหม กดรูปดวงตาท้ายช่องรหัสผ่านได้

> ครั้งแรกของวันอาจรอนานประมาณ 30-60 วินาที เป็นเรื่องปกติ เซิร์ฟเวอร์กำลังตื่นจากโหมดพัก ไม่ใช่ระบบเสีย ครั้งต่อไปจะเร็วทันที

--------------------------------------------------
## หน้าแรก

หลังเข้าสู่ระบบจะเห็นรูปโปรไฟล์ ชื่อ และตำแหน่งของตัวเอง ถัดลงมามีกล่องสรุป 3 กล่อง กดที่กล่องไหนก็เข้าไปหน้านั้นได้เลย

| กล่อง | กดแล้วไปไหน |
| --- | --- |
| นักเรียนทั้งหมด | หน้าจัดการสมาชิก |
| นัดหมายทั้งหมด | หน้าจัดการนัดหมาย |
| นัดหมายที่รอดำเนินการ | หน้าจัดการนัดหมาย |

ล่างสุดมีกราฟ 3 อัน คือสัดส่วนโรคประจำตัว จำนวนคนเข้ารับบริการรายวัน และรายเดือน ปกติจะย่อไว้ กดลูกศรมุมขวาเพื่อกางดู

**เมนูทั้งหมดอยู่ที่ปุ่มขีดสามขีดมุมซ้ายบน** กดแล้วเมนูจะเลื่อนออกมา

--------------------------------------------------
## เพิ่มนักเรียนเข้าระบบ

1. เปิดเมนูขีดสามขีด เลือก **จัดการสมาชิก**
2. กดปุ่ม **+** ที่หัวตารางด้านขวา
3. กรอกข้อมูล
   * เลือกขอบเขตของบัญชี เป็น User (นักเรียน/นักศึกษา)
   * ชื่อผู้ใช้และรหัสผ่าน (รหัสผ่านเป็นตัวเลข 5 หลัก)
   * ชื่อ นามสกุล ชื่อเล่น
   * อีเมล (สำคัญมาก ถ้าไม่ใส่จะส่งแจ้งเตือนหาไม่ได้)
   * รหัสนักเรียน ระดับชั้น สาขาวิชา
4. อยากใส่รูปโปรไฟล์ กด **เลือกรูปภาพ** แล้วลากปรับตำแหน่งในวงกลม เลื่อนแถบเพื่อซูม แล้วกดบันทึก
5. กด **เพิ่มสมาชิก**

จะมีเครื่องหมายถูกสีเขียวขึ้นมาบอกว่าสำเร็จ แล้วหายไปเอง

**เพิ่มบัญชีพยาบาลคนใหม่** ทำเหมือนกัน แค่เปลี่ยนขอบเขตของบัญชีเป็น Admin แล้วกรอกตำแหน่ง เช่น พยาบาลวิชาชีพ

--------------------------------------------------
## ค้นหานักเรียน

ในหน้าจัดการสมาชิก ช่องค้นหาอยู่ด้านบน ค้นได้ 3 แบบ ใช้พร้อมกันได้

* รหัสนักศึกษา
* ระดับชั้น
* สาขาวิชา

กด **ค้นหา** แล้วรายชื่อด้านล่างจะกรองให้ กด **ล้างการค้นหา** เพื่อกลับมาดูทั้งหมด

--------------------------------------------------
## ดูประวัตินักเรียนรายคน

ในหน้าจัดการสมาชิก **คลิกที่แถวชื่อนักเรียน** ได้เลย จะเข้าหน้าประวัติที่รวมทุกอย่างไว้

* ข้อมูลส่วนตัว กรุ๊ปเลือด โรคประจำตัว
* ประวัติแพ้ยา เพิ่มหรือแก้ไขได้จากหน้านี้
* ประวัติการเข้ารับบริการทั้งหมด
* นัดหมายทั้งหมด

ล่างสุดมีปุ่ม **ส่งออกเป็น PDF** กดแล้วได้ไฟล์ประวัติของนักเรียนคนนั้นไว้พิมพ์หรือเก็บเข้าแฟ้ม

--------------------------------------------------
## บันทึกการเข้ารับบริการ

เมื่อนักเรียนเข้ามาใช้บริการห้องพยาบาล

1. เปิดเมนู เลือก **บันทึกการเข้ารับบริการ**
2. กดปุ่ม **+**
3. ค้นหานักเรียนด้วยรหัสนักศึกษา ระดับชั้น หรือสาขา แล้วเลือกชื่อ
4. กรอกอาการ การวินิจฉัย การรักษา และยาที่จ่าย
5. กดบันทึก

ประวัตินี้จะไปแสดงในหน้าประวัติของนักเรียนคนนั้น และนักเรียนเปิดดูเองได้จากบัญชีของตัวเอง

--------------------------------------------------
## สร้างนัดหมาย

ระบบออกแบบให้นัดหมายหลายคนพร้อมกันได้ โดยใส่ลงตะกร้าก่อน ตรวจทานให้ครบ แล้วค่อยกดสร้างทีเดียว

1. เปิดเมนู เลือก **จัดการนัดหมาย**
2. กดปุ่ม **+**
3. เลือกนักเรียน กำหนดวันและเวลา ใส่เหตุผลการนัด
4. กด **เพิ่มลงรายการ** ฟอร์มจะว่างให้กรอกคนถัดไปได้ทันที
5. ทำซ้ำจนครบทุกคน รายการที่เพิ่มไว้จะแสดงเป็นการ์ดด้านล่าง แก้ไขหรือลบออกได้
6. กด **สร้างนัดหมายทั้งหมด**

ระบบจะส่งอีเมลแจ้งนักเรียนทุกคนในรายการอัตโนมัติ

**นัดคนเดียว** ก็ใช้วิธีเดียวกัน แค่เพิ่มลงรายการคนเดียวแล้วกดสร้างเลย

--------------------------------------------------
## ส่งแจ้งเตือน

มีสองแบบ

**ส่งเฉพาะบางคน** ใช้ตะกร้าเหมือนการสร้างนัดหมาย เลือกนักเรียน พิมพ์ข้อความ กดเพิ่มลงรายการ ทำซ้ำจนครบ แล้วกดส่งทั้งหมด

**ประกาศให้ทุกคน** ติ๊กช่อง "ส่งเป็นประกาศให้ทุกคน" พิมพ์ข้อความครั้งเดียว แล้วกดส่ง ระบบจะส่งให้นักเรียนทุกคนที่มีอีเมลในระบบ

> ระบบส่งอีเมลได้วันละ 300 ฉบับ ถ้ามีนักเรียนมากกว่านั้น การประกาศให้ทุกคนในวันเดียวจะส่งไม่ครบ ให้แบ่งส่งเป็นสองวัน

--------------------------------------------------
## ปัญหาที่พบบ่อย

| อาการ | ทำยังไง |
| --- | --- |
| เข้าเว็บครั้งแรกแล้วหมุนนาน | รอ 30-60 วินาที เซิร์ฟเวอร์กำลังตื่นจากโหมดพัก ไม่ใช่ระบบเสีย |
| หน้าจอค้าง หรือแสดงผลแปลก ๆ | กด `Ctrl+Shift+R` เพื่อโหลดหน้าใหม่ทั้งหมด |
| นักเรียนบอกว่าไม่ได้รับอีเมล | ให้เขาเช็คในกล่องจดหมายขยะก่อน แล้วดูว่าอีเมลในระบบสะกดถูกไหม |
| ส่งประกาศแล้วบางคนไม่ได้รับ | อาจเกินโควตา 300 ฉบับต่อวัน ลองส่งใหม่วันถัดไป |
| ลืมรหัสผ่านตัวเอง | ให้พยาบาลอีกคนที่มีบัญชี Admin เข้าไปตั้งรหัสใหม่ให้ที่หน้าจัดการสมาชิก |

--------------------------------------------------
## สิ่งที่นักเรียนทำได้ด้วยตัวเอง

เมื่อนักเรียนเข้าสู่ระบบด้วยบัญชีของตัวเอง จะเห็นเมนูเหล่านี้

* แก้ไขข้อมูลส่วนตัวและเปลี่ยนรูปโปรไฟล์
* บันทึกประวัติแพ้ยาของตัวเอง
* ดูนัดหมายทั้งหมดที่มี
* อ่านการแจ้งเตือนที่ได้รับ
* ดูประวัติการเข้าใช้งานระบบ
* ดูประวัติการเข้ารับบริการห้องพยาบาลย้อนหลัง

นักเรียนแก้ไขประวัติการรักษาที่พยาบาลบันทึกไว้ไม่ได้ ดูได้อย่างเดียว

--------------------------------------------------
## ข้อควรระวัง

* ข้อมูลในระบบเป็นข้อมูลสุขภาพของนักเรียนจริง ไม่ควรเปิดหน้าจอทิ้งไว้โดยไม่มีคนดูแล
* ใช้งานเสร็จแล้วกดออกจากระบบทุกครั้ง โดยเฉพาะถ้าใช้เครื่องที่มีคนอื่นใช้ร่วมด้วย
* การลบสมาชิกจะลบประวัติการรักษา นัดหมาย และการแจ้งเตือนของคนนั้นไปทั้งหมด กู้กลับไม่ได้

# ส่วนสำหรับผู้ดูแลระบบและนักพัฒนา

ตั้งแต่ตรงนี้ลงไปเป็นรายละเอียดทางเทคนิค พยาบาลไม่จำเป็นต้องอ่าน

--------------------------------------------------
## ภาพรวมโครงสร้าง

โปรเจกต์แยกเป็นสองที่เก็บ เพราะหน้าเว็บกับเซิร์ฟเวอร์ deploy คนละที่กัน

| ส่วน | ที่เก็บโค้ด | รันอยู่ที่ |
| --- | --- | --- |
| หน้าเว็บ (React) | `hospital-frontend` | Vercel |
| เซิร์ฟเวอร์ (PHP API) | `hospitalback-end` | Render |

--------------------------------------------------
## บริการที่ระบบพึ่งพา

ระบบไม่ได้รันอยู่บนเซิร์ฟเวอร์เดียว แต่กระจายไปตามบริการที่ถนัดคนละอย่าง

| บริการ | ทำหน้าที่ | ทำไมต้องใช้ |
| --- | --- | --- |
| Vercel | เสิร์ฟหน้าเว็บ React | ฟรี เร็ว และ deploy ใหม่อัตโนมัติทุกครั้งที่ push ขึ้น GitHub |
| Render | รัน PHP + Apache ผ่าน Docker | รองรับ PHP ซึ่ง Vercel ไม่รองรับ |
| Railway | ฐานข้อมูล MySQL 8 | Render ไม่มี MySQL ให้ใช้ฟรี |
| Cloudinary | เก็บไฟล์รูปโปรไฟล์ | Render ล้างไฟล์ทิ้งทุกครั้งที่ deploy ใหม่ เก็บรูปไว้ในเครื่องไม่ได้ |
| Brevo | ส่งอีเมลผ่าน HTTP API | Render ปิดพอร์ต SMTP ขาออก ส่งผ่าน Gmail โดยตรงไม่ได้ |

--------------------------------------------------
## เครื่องมือที่ใช้

ฝั่งหน้าเว็บ

* React 18 กับ Vite
* React Router สำหรับสลับหน้า
* CSS เขียนเองทั้งหมด ไม่ได้ใช้ไลบรารีสำเร็จรูป ธีมอยู่ในไฟล์เดียวคือ `src/index.css`
* ฟอนต์ Prompt สำหรับหัวข้อ และ Sarabun สำหรับเนื้อหา
* กราฟทั้งหมดวาดด้วย CSS ล้วน ไม่ได้ติดตั้งไลบรารีกราฟเพิ่ม

ฝั่งเซิร์ฟเวอร์

* PHP 8.2 กับ Apache
* MySQL 8
* PHPMailer และ mPDF ติดตั้งผ่าน Composer
* ตอบกลับเป็น JSON ทั้งหมด ไม่มีการ render HTML จากฝั่งเซิร์ฟเวอร์

--------------------------------------------------
## ความต้องการของระบบ

ถ้าจะรันเองบนเครื่อง

* PHP 8.2 พร้อมส่วนขยาย PDO_MySQL, mysqli, mbstring, curl
* MySQL 8 (ถ้าใช้ MariaDB ของ XAMPP จะเชื่อมต่อ MySQL 8 บน Railway ไม่ได้ เพราะไม่รองรับ caching_sha2_password)
* Apache ที่เปิด mod_rewrite
* Node.js 18 ขึ้นไป สำหรับ build หน้าเว็บ
* Composer สำหรับติดตั้ง PHPMailer และ mPDF

หรือใช้ Docker Desktop อย่างเดียว แล้วข้ามทั้งหมดข้างบนไปได้เลย

### ฝั่งเซิร์ฟเวอร์ (hospitalback-end)

```
hospitalback-end/
├── api/
│   ├── auth/                    เข้าสู่ระบบ / สมัครสมาชิก / ออกจากระบบ / เช็คสถานะ
│   ├── student/                 API ของนักเรียน - โปรไฟล์, แพ้ยา, นัดหมาย, ประวัติ, อัปโหลดรูป
│   └── admin/                   API ของพยาบาล - จัดการสมาชิก, บันทึกการรักษา, นัดหมาย, แจ้งเตือน, PDF
├── config/
│   ├── db_connect.php           เชื่อมต่อฐานข้อมูล อ่านค่าจาก environment ถ้ามี ไม่มีก็ใช้ localhost
│   └── mail_config.php          * ไม่ขึ้น git - รหัสผ่าน Gmail สำหรับทดสอบส่งอีเมลในเครื่อง
├── includes/
│   ├── bootstrap.php            ตั้งค่า CORS ตรวจ token และฟังก์ชันตอบกลับ JSON ที่ทุก API เรียกใช้
│   ├── auth_token.php           อ่าน Bearer token จาก header แล้วเทียบกับตาราง tb_sessions
│   ├── send_email.php           ส่งอีเมล ใช้ Brevo API ถ้ามีคีย์ ไม่มีก็ถอยไปใช้ SMTP
│   └── cloudinary.php           อัปโหลดรูปขึ้น Cloudinary แล้วคืน URL กลับมา
├── sql/
│   └── create_tb_sessions.sql   คำสั่งสร้างตารางเก็บ token
├── fonts/                       ฟอนต์ Sarabun สำหรับพิมพ์ PDF ภาษาไทย
├── assets/                      โลโก้วิทยาลัย
├── vendor/                      PHPMailer และ mPDF (ติดตั้งผ่าน Composer)
├── init-db/                     * ไม่ขึ้น git - วางไฟล์ .sql ไว้ที่นี่ให้ Docker นำเข้าอัตโนมัติ
└── Dockerfile                   สูตร build อิเมจที่ Render ใช้ตอน deploy จริง
```

## ติดตั้งด้วย Docker (วิธีที่เร็วที่สุด)

เหมาะกับคนที่อยากลองระบบโดยไม่ต้องติดตั้ง XAMPP, PHP, MySQL, Node ทีละอย่าง ต้องมีแค่ Docker Desktop กับ Git

```bash
mkdir hospital-system
cd hospital-system
git clone https://github.com/famozy3508-gif/hospitalback-end.git backend
git clone https://github.com/famozy3508-gif/hospital-frontend.git frontend
```

วางไฟล์ `docker-compose.yml` ไว้ที่โฟลเดอร์ `hospital-system/` ให้ได้โครงสร้างแบบนี้

```
hospital-system/
├── backend/
├── frontend/
└── docker-compose.yml
```

แล้วสั่ง

```bash
docker compose up -d
```

ครั้งแรกใช้เวลาประมาณ 3-5 นาที เพราะต้องโหลดอิเมจและติดตั้ง node_modules ครั้งต่อไปจะเร็วมาก ดูความคืบหน้าได้ด้วย `docker compose logs -f frontend`

เสร็จแล้วเปิด

| ที่อยู่ | คืออะไร |
| --- | --- |
| http://localhost:5173 | หน้าเว็บ เข้าใช้งานจริงที่นี่ |
| http://localhost:8080/api/auth/me.php | ทดสอบเซิร์ฟเวอร์ ถ้าได้ `{"logged_in":false}` คือปกติ |
| http://localhost:8081 | phpMyAdmin เข้าด้วย user `root` ไม่ต้องใส่รหัสผ่าน |

### ใส่ข้อมูลเริ่มต้น

ฐานข้อมูลที่ Docker สร้างให้จะว่างเปล่า ยังไม่มีตารางเลย ให้สร้างโฟลเดอร์ `backend/init-db` แล้วเอาไฟล์ `.sql` ที่ export ไว้ไปวาง จากนั้นสั่งสร้างใหม่

```bash
docker compose down -v
docker compose up -d
```

> คำสั่งนำเข้าอัตโนมัติทำงานแค่ตอนสร้างฐานข้อมูลครั้งแรกเท่านั้น ถ้าเคยรันไปแล้วต้องใช้ `down -v` เพื่อล้างของเดิมก่อน ข้อมูลบน Railway ไม่ได้รับผลกระทบ

ค่าเริ่มต้นของฐานข้อมูลคือ user `root` ไม่มีรหัสผ่าน ตรงกับ XAMPP พอดี ไม่ต้องแก้อะไรถ้ายังไม่ได้ตั้ง environment variables

## ชี้ไปที่เซิร์ฟเวอร์ตัวไหน

ทั้งระบบคุยกับเซิร์ฟเวอร์ผ่านตัวแปรเดียวคือ `API_BASE` ในไฟล์ `src/api/client.js` มีสองบรรทัดเตรียมไว้ให้แล้ว

```js
// ใช้เซิร์ฟเวอร์จริง
export const API_BASE = 'https://hospitalback-end.onrender.com/api';

// ใช้เซิร์ฟเวอร์ในเครื่อง
// export const API_BASE = 'http://localhost:8080/api';
```

สลับด้วยการคอมเมนต์บรรทัดที่ไม่ใช้

> ก่อน push ขึ้น GitHub ทุกครั้ง ต้องเช็คว่าบรรทัดที่เปิดใช้อยู่คือเซิร์ฟเวอร์จริง ถ้าเผลอ push บรรทัด localhost ขึ้นไป เว็บบน Vercel จะเรียกเซิร์ฟเวอร์ไม่ได้ทั้งระบบ

--------------------------------------------------
## ค่าตั้งค่าที่เซิร์ฟเวอร์จริงต้องมี

ทั้งหมดอ่านผ่าน `getenv()` ไม่มีค่าไหนฝังอยู่ในโค้ด ถ้าไม่ได้ตั้งไว้ ระบบจะถอยไปใช้ค่า localhost แทน ซึ่งบนเซิร์ฟเวอร์จริงจะเชื่อมต่อไม่ได้และเงียบหายไปเฉย ๆ

| กลุ่ม | ตัวแปร |
| --- | --- |
| ฐานข้อมูล | `DB_HOST` `DB_PORT` `DB_NAME` `DB_USER` `DB_PASSWORD` |
| รูปภาพ | `CLOUDINARY_CLOUD_NAME` `CLOUDINARY_API_KEY` `CLOUDINARY_API_SECRET` |
| อีเมล | `BREVO_API_KEY` `SMTP_USERNAME` `SMTP_FROM_NAME` |

ตั้งค่าได้ที่ Render Dashboard แท็บ Environment เมื่อบันทึกแล้วระบบจะ deploy ใหม่ให้เอง

--------------------------------------------------
## การนำขึ้นเซิร์ฟเวอร์

ทั้งสองที่เก็บผูกกับบริการไว้แล้ว push ขึ้น branch `main` เมื่อไหร่ ระบบจะ build และเผยแพร่ให้เองอัตโนมัติ ไม่ต้องสั่งอะไรเพิ่ม

ค่าที่ตั้งไว้ใน Vercel สำหรับหน้าเว็บ

| ช่อง | ค่า |
| --- | --- |
| Build Command | `npm run build` |
| Output Directory | `dist` |
| Install Command | `npm install` |

ฝั่ง Render ใช้ `Dockerfile` ในที่เก็บเซิร์ฟเวอร์ build เอง ไม่ต้องตั้งค่าคำสั่งอะไรเพิ่ม

ไฟล์ `vercel.json` มีไว้แก้ปัญหาเฉพาะของเว็บแบบหน้าเดียว เวลาผู้ใช้กดรีเฟรชขณะอยู่หน้าอื่นที่ไม่ใช่หน้าแรก Vercel จะพยายามหาไฟล์ตามชื่อ URL นั้นแล้วไม่เจอ ขึ้น 404 ไฟล์นี้บอกให้ส่ง `index.html` กลับไปเสมอ แล้วปล่อยให้ React Router จัดการเอง

## สิ่งที่ควรรู้

* ใช้พอร์ต 5173, 8080, 8081 และ 3307 เพื่อไม่ให้ชนกับ XAMPP ที่ใช้ 80 กับ 3306 เปิดพร้อมกันได้
* รหัสผ่านใน `docker-compose.yml` มีไว้สำหรับรันบนเครื่องตัวเองเท่านั้น ห้ามเอาไปใช้บนเซิร์ฟเวอร์จริง
* Render แผนฟรีจะพักการทำงานเมื่อไม่มีคนใช้ 15 นาที คนแรกที่เข้าหลังจากนั้นต้องรอ 30-60 วินาที ไม่ใช่ระบบพัง
* Brevo แผนฟรีส่งได้ 300 ฉบับต่อวัน ต้องระวังตอนใช้โหมดประกาศให้ทุกคน
* หลัง deploy เวอร์ชันใหม่ ให้กด `Ctrl+Shift+R` ที่หน้าเว็บ ไม่งั้นเบราว์เซอร์จะยังใช้ไฟล์เก่าที่ค้างอยู่
* เปิดที่อยู่หลักของเซิร์ฟเวอร์แล้วเจอ Forbidden เป็นเรื่องปกติ เพราะไม่มีหน้าเว็บให้แสดง มีแต่ API

## ความปลอดภัย

* รหัสผ่านเก็บด้วย `password_hash()` (bcrypt) ไม่มีที่ไหนเก็บเป็นข้อความธรรมดา
* ทุก API ต้องแนบ `Authorization: Bearer <token>` และตรวจสิทธิ์ตามบทบาทฝั่งเซิร์ฟเวอร์เสมอ ไม่เชื่อค่าที่ส่งมาจากหน้าเว็บ
* token เก็บในตาราง `tb_sessions` อายุ 7 วัน ออกจากระบบเมื่อไหร่จะถูกลบทันที ใช้ต่อไม่ได้อีก
* ระบบเคยใช้ session cookie แต่เปลี่ยนมาใช้ token เพราะเบราว์เซอร์บนมือถือบล็อก cookie ข้ามโดเมน ทำให้เข้าใช้จากมือถือไม่ได้เลย
* `config/mail_config.php` และโฟลเดอร์ `init-db/` ถูกกันไว้ใน `.gitignore` รหัสผ่านและข้อมูลสุขภาพนักเรียนจะไม่ขึ้น git
* CORS อนุญาตเฉพาะโดเมนที่ระบุไว้ใน `bootstrap.php` เท่านั้น

## หมายเหตุสำหรับผู้พัฒนาต่อ

* `src/api/client.js` เป็นจุดเดียวที่กำหนดที่อยู่เซิร์ฟเวอร์และแนบ token ถ้าจะย้ายเซิร์ฟเวอร์ แก้ที่นี่ที่เดียว
* `includes/bootstrap.php` ถูกเรียกที่บรรทัดแรกของทุกไฟล์ API ถ้าจะเพิ่มการตรวจสอบอะไรที่ต้องใช้ทุกที่ ใส่ตรงนี้
* จะเปลี่ยนสีหรือฟอนต์ทั้งระบบ แก้ตัวแปรที่บล็อก `:root` บนสุดของ `src/index.css`
* จะเพิ่มหน้าใหม่ ต้องเพิ่มเส้นทางใน `App.jsx` และครอบด้วย `ProtectedRoute` ถ้าหน้านั้นต้องล็อกอินก่อน
* `ImageCropper.jsx` เขียนแบบไม่ผูกกับหน้าไหน รับแค่ไฟล์เข้าไปแล้วคืนไฟล์ที่ครอปแล้วออกมา ใช้ซ้ำได้ทั้งฝั่งพยาบาลและฝั่งนักเรียน
* `StatusModal.jsx` และ `LoadingScreen.jsx` ใช้ `createPortal` ย้ายตัวเองไปแปะที่ `body` เพราะกล่องแม่มี `backdrop-filter` ซึ่งทำให้ `position: fixed` ไม่ยึดกับหน้าจอตามที่ควรจะเป็น
* หน้าจัดการนัดหมายกับหน้าส่งแจ้งเตือนใช้แนวคิดตะกร้าแบบเดียวกัน ชื่อ state และฟังก์ชันตั้งให้ตรงกันไว้แล้ว แก้ที่หนึ่งแล้วเทียบอีกที่ได้เลย
* ฐานข้อมูลมี 8 ตาราง ชื่อขึ้นต้นด้วย `tb_` ทั้งหมด ความสัมพันธ์ผูกกับ `tb_users.user_id` เป็นหลัก
